# MCP ↔ CatchAll API v1.5.3 full sync — verification note

Date: 2026-06-03 · Branch: `feat/v1.53.0_release`

## Goal
Make the MCP server expose the **exact same functionality as the CatchAll API**.
Before this work the server had 22 tools covering Jobs, Monitors, a partial
Webhook slice, and User/Meta. It now has **57 tools — one for every API endpoint**.

The live API reports version 1.6.0; its endpoint set is the v1.5.3 fixture plus one
extra (`GET /catchAll/webhook-history`), which is also covered. Request DTOs were
diffed between the v1.5.3 fixture and the live spec — no drift.

## How it was verified — real API, full lifecycle
Driven through the **real MCP protocol** (stdio `tools/call`), not direct function
calls. Each create→read→update→delete lifecycle ran against the live API and
everything created was deleted afterwards (account left as found).

- **37/37 functional checks passed** across all families (meta, validate, webhooks
  + resources + history, entities, datasets incl. CSV, projects, submit-with-assoc,
  monitor lifecycle on a completed base job).
- Integration suite (`tests/integration/`) run against a locally-started server:
  64 passed, 1 skipped (monitor-creating lifecycle is opt-in). The only failures
  were a transient `Jobs_Concurrency` (4/4) cap hit by the suite's *own* job
  submissions — unrelated to these changes.
- Bundled unit suite (`tests/test_server.py`): 22 passed, 50 subtests.

## Real-API behavior worth knowing (trusted over the spec)
- **Webhook `auth` is an object**, not `[user, pass]`: `{"type":"bearer","token":…}`,
  `{"type":"api_key","header":…,"value":…}`, or `{"type":"basic","username":…,"password":…}`.
- **Webhook `method`** accepts the full enum (GET/POST/PUT/PATCH/DELETE) — a live
  webhook on the account uses GET.
- **Monitors use centralized `webhook_ids`** (the v1.5.2 inline `webhook` object is gone),
  and **monitors are not supported for `lite` jobs** — the reference job must be `base`.
- **`submit_query` `webhook_ids` must reference active webhooks** — a disabled
  (`is_active=false`) webhook is rejected.
- **CSV upload requires `name` and `domain` columns**; rows missing `domain` are
  skipped and reported in `validation_report.skipped_rows`.
- **CSV-uploaded entities persist** as standalone entities even after their dataset
  is deleted (delete them with `delete_entity` to fully clean up).

## Test reconciliation (stale tests updated, with proof)
Changing the monitor signature and removing the inline-webhook helpers made some
bundled tests stale (they asserted the v1.5.2 inline-webhook contract). Because the
**real API** confirms monitors now take `webhook_ids`, these were updated — not to
force a pass, but to match the verified new contract:
- `tests/test_server.py`: replaced `validate_webhook_method` / `build_webhook_payload`
  / list-form `validate_webhook_auth` tests with tests for the new validators
  (`validate_http_method`, `validate_choice`, object-form `validate_webhook_auth`);
  updated monitor request-mapping to `webhook_ids`; added mapping tests for new tools.
- `tests/integration/test_monitors.py`: dropped inline-webhook tests, added
  `delete_monitor` / `get_monitor_status` error tests, switched lifecycle update to `limit`.
- `tests/integration/test_tools_listed.py`: expanded the expected-tool set to all 57.
- `tests/integration/test_v153_surface.py`: new safe (no paid-resource) tests for
  validate, list surfaces, enum validation, and not-found handling.
